# 数据同步 · 部署 · 前瞻验证 说明

> 配套文件：`index.html`（工具页，含「2. 7码候选」「5. 数据同步」「6. 前瞻验证」模块）、
> `scripts/sync-am.js`（抓取解析脚本）、`.github/workflows/sync-lottery.yml`（定时同步）、
> `data/am-latest.json`（仓库内数据源，前端"一键同步"读取的就是它）、
> `tests/`（自动测试，见第八节）。

## 一、整体设计

```
源站 am.html ──(GitHub Actions 定时抓取，带浏览器 headers)──▶ scripts/sync-am.js
      403/失败时：不改文件、workflow 红叉并输出 ::error::            │
                                                                   ▼
                                                     data/am-latest.json （commit & push）
                                                                   │
浏览器 index.html ──fetch('./data/am-latest.json')──▶ 只追加本地缺失的连续期号 ──▶ localStorage
      读取失败时：提示使用「粘贴导入」兜底（解析 HTML / 纯文本 / Markdown）
```

- 内置数组 `COMPRESSED_DATA` 保持不变（截至 2026-200），任何同步/测试流程都不得修改或删除它。
- 所有新增开奖数据只写入 localStorage，与内置数据在内存中拼接使用。
- 前端不直连源站（浏览器会被 403 拦截），只读同仓库的 JSON。

## 二、部署 GitHub Pages

1. 把本仓库推到 GitHub（含 `data/`、`scripts/`、`.github/workflows/`）。
2. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支选 `main`，目录 `/ (root)`，保存。
3. 约 1 分钟后访问 `https://<用户名>.github.io/<仓库名>/`。
4. 注意：`index.html` 为单文件应用，所有 CSS/JS 均已内嵌；`sw.js`/`manifest.json` 为 PWA 可选文件。

## 三、GitHub Actions 同步

- 自动运行：每天 UTC 13:40 与 15:10（约北京时间 21:40 / 23:10，开奖后）各尝试一次。
- 手动运行：仓库 **Actions → Sync lottery data → Run workflow** → 点绿色按钮。
- 只在 `data/am-latest.json` 内容变化时才 commit & push（bot 提交：`chore(data): sync am-latest.json …`）。
- 无变化时正常退出（绿色），不会产生空提交。

## 四、如果 Actions 报 403

脚本的退出码约定：`0` 成功（含无变化）、`2` 抓取失败（403/网络）、`3` 抓取成功但解析出 0 条。
失败时**保证不改动** `data/am-latest.json`，并在日志里输出 `::error::` 原因与排查建议。

按顺序处理：

1. 打开 Actions 失败那次运行的日志，看具体是 403、超时还是解析失败。
2. 用**家庭网络的浏览器**打开 `https://2026kj.zkclhb.com:2025/am.html`：
   - 浏览器也打不开 → 源站本身故障，等恢复即可，仓库 JSON 不受影响。
   - 浏览器能打开 → 源站屏蔽了 GitHub Actions 的数据中心 IP。两种替代：
     a. 在本地电脑运行 `node scripts/sync-am.js`（需 Node 18+），成功后把 `data/am-latest.json` 手动提交推送；
     b. 直接用工具页面的「粘贴导入」：复制网页内容 → 粘贴 → 解析并追加缺失期（写入的只是本机 localStorage，不影响仓库）。

## 五、工具页使用

- **一键同步**：读取仓库 `data/am-latest.json`（备选 `data/am-2026.json`），对比本地最后一期，只追加缺失的**连续**期号到 localStorage；状态栏会显示本地最后一期 / 数据源最新一期 / 本次追加期数 / 是否已是最新 / 冲突与缺口。
- **仅检查**：同样的读取与对比，但不写入。
- **粘贴导入**：粘贴源网页正文、HTML 源码或 Markdown 表格均可，支持「242 期(开奖时间:2026-08-30) + 7 行号码」等多种版式；解析预览无风险，确认后再追加。
- 期号缺口保护：数据不连续时不会写入，并明确提示缺哪一期（先补齐缺口期即可继续）。
- 冲突保护：期号相同但号码不同时保留本地值并明确列出，不会被数据源覆盖。
- **组合约束开关**（「2. 7码候选」内，默认关闭）：可选实验，不是默认模型，每次刷新页面恢复关闭。开启后候选 7 码、历史回放与前瞻验证按组合约束规则重算，并取消/清空旧的随机对照（见第七节规则说明）。

## 六、精确检验、起算期与随机对照

「6. 前瞻验证」默认起算期 `2026-201`。注意：这只**是评估区间的默认值，不代表模型参数在该期前已冻结**——模型是在全部已有历史上调参得到的。历史回放≠参数提前冻结；反复更换起算期、挑显著区间属于多重检验/选择偏差。

### 无未来信息与自检

1. **无未来信息**：验证第 N 期时只把第 N 期**之前**的数据喂给模型（等价于历史回放的 `longWaveEngine(draws.slice(0,i))`）。页面上任意一期的 7 码应与"历史回放"中该期的固定 7 码完全一致。
2. **追加数据不改历史预测**：一键同步/粘贴导入追加新数据后，早期期次的预测 7 码保持不变。
3. **明细逐行可查**：每期仅列期号、当期 7 码、实际特码、7码是否命中，可人工复核；不再计算或展示单双、大小、波色的前瞻命中列。
4. **整体校验**：一期 7 码的随机命中概率恒为 7/49≈14.29%；把起算期改更早（如 `2026-001`），样本期数应随之变大且历史回放中该年总命中数一致。

### 精确二项右尾检验

- 原假设：各期开奖独立且特码在 1–49 中均匀分布；每期固定 7 个不同候选，单期命中概率 `p0 = 7/49 = 1/7`。
- `N` 为实际回放期数、`K` 为命中次数，主检验为 `P[Binomial(N, 1/7) >= K]`（含等号）。
- 实现 `binomRightTail(N,K)`：每个项的 log-PMF 用 log 求和独立计算（**不计算阶乘**，不用 `1-CDF` 相减），再在 log 域做 log-sum-exp 累加（Kahan 补偿），避免溢出、下溢与尾部消减误差。超出浮点表示范围的极小尾概率显示为 `<1e-300`，绝不显示为"概率绝对为零"。
- 连续性修正 `z = (K − N/7 − 0.5) / sqrt(N × (1/7) × (6/7))` **仅作参考展示，不参与显著性判定**。
- 判定规则：只有精确 `p < 0.05` 才标"统计显著（单一区间、未校正）"；`0.05 <= p < 0.10` 标"边缘 / 不显著（可能为随机波动）"；其余不显著。
- 核对点：`N=58, K=13` 时精确 `p ≈ 0.06298880271203224`（边缘/不显著）；`K=14` 时 `≈ 0.03135150682202337`（显著）。
- 无样本时不显示 p/z、不运行模拟；`K=0` 时精确右尾为 1。命中率不是收益率。

### 动态起算期（输入框 + 滑块）

- 期号输入框与滑块**双向同步**；拖动滑块即时更新，输入防抖后自动重算；「重新计算」按钮仍可手动触发。
- 起算期只改变评估区间，各期预测仍使用**该期之前的完整历史**（不截断、不偷看）。模型最少需要 60 期预热：早于预热期的起点自动从第 61 期起算，并显示有效区间。
- 错误/超出范围的期号**明确报错，不静默回退默认起点**。
- 追加、撤销、修复、导入数据后，前瞻缓存、滑块边界与有效区间都会更新。
- 反复拖动、重复查看、事后择优区间属于探索性分析，不能消除基准期偏误；本页没有多重检验校正。正式验证必须**提前**固定版本、起算期、观察期限，只使用其后未见的数据。

### 蒙特卡洛 10,000 次随机对照

- 按当前相同的 `N` 模拟 10,000 个随机模型，统计命中次数 `>= K` 的比例作为经验 p；用独立 `Bernoulli(1/7)` 逐期抽取（与"抽 7 个不同号码再查命中"完全同分布），避免构造无用的完整号码集合；对照组不应用组合约束。
- PRNG 为 Mulberry32，随机种子由浏览器随机源生成并**显示**，计算分批让出主线程并显示进度。
- 展示：随机种子、超过次数、经验 p、模拟比例的 95% Wilson 区间、精确右尾 p 对照。区间衡量**模拟误差**，不是模型胜率区间；超过次数为 0 也不代表真实概率为 0。
- 切换起算期、切换组合约束开关或更新数据时，**立即取消旧任务并清空旧结果**，防止统计串区间。蒙特卡洛只是交叉核对，显著性仍只由精确检验决定。

## 七、恢复原评分与选码，组合约束保留为可选实验

算法实现均在 `index.html`，没有新增浏览器运行依赖，**页面不显示模型版本号**。

1. **默认评分**：原饱和度评分档位（85%–90% 档 45 分、破纪录档 25 分），近 150 期频次 ×3，近 45 期最少波色 +14 分。不做极冷码评分软化、熵正则化或评分平滑。这是恢复旧规则，不是证明旧规则有预测能力。
2. **默认选码**：原版前 5 个按评分、#6–7 沿用原分区软约束及 80% 分数阈值的逻辑。已与原始引擎逐期核对 1294 组有序 7 码（哈希回归，见第八节）。
3. **可选组合约束**：「2. 7码候选」的"启用组合约束"开关默认关闭。开启后：按原评分排名（分数降序、号码升序）取前 10 码，在其中选**原总分最高**的 7 码组合，须同时满足和值 `[140,210]`、单数 2–5 个、任一波色不超过 4 个；同分组合优先取排名更靠前的号码。
4. **无解兜底**：前 10 码无解时按排名逐个扩池（11、12、…），取第一个有解池的最优组合，**不放宽约束、不输出不足 7 码**。页面展示当前池大小、原总分、和值、单数与波色分布。
5. **切换隔离**：开关切换会重算候选号码、历史回放和前瞻验证，并取消/清空旧随机对照；前瞻与随机对照缓存按"数据版本 × 模型配置 × 起算期"隔离。不修改开奖数据。

### 拆分回测结论（截至 2026-258）

逐期仅用此前历史，没有根据各方案结果搜索新参数。共测旧版基准与若干预列出的拆分方案（离线核对，未写入页面）：

| 方案 | 全部1294期命中 | 2026年258期命中 | 最近58期命中 |
|---|---:|---:|---:|
| 原评分＋原选码（当前默认） | 230 | 53 | 13 |
| 原评分＋组合约束（可选） | 217 | 47 | 10 |
| 仅软化极冷评分 | 189 | 41 | 10 |
| 上一轮整套改动 | 196 | 44 | 10 |

**没有任何改动显示出相对旧版的显著提升。** 原评分＋组合约束在全量样本中，改进方案单独命中 35 次、旧版单独命中 48 次；配对单边改善检验 `p≈0.93807`（不是随机 7 码基线检验），不能说明组合约束更好。

默认最近 58 期命中 13 次，精确随机基线右尾 `p≈0.06298880`，应标"边缘 / 不显著"；开启组合约束后为 10 次，`p≈0.31181423`，不显著。不能把"优于纯随机"与"优于原算法"混淆，也不能把历史结果直接当作未来胜率。

### 已删除的实验：评分平滑（仅留档）

上一轮实验用过 `q = softmax(rawScore/12)`、`w = 0.75q + 0.25/49`、最终评分 `ln(w)`。它压缩分数差距、向均匀权重收缩，不改变单码排名；理论上可能改变组合总分比较选出的组合。该实验 1294 期中加/不加平滑的最终 7 码集合完全相同，未产生可观察到的命中收益，**已从生产页面删除**，此处仅留公式备查。

## 八、自动测试

在仓库根目录运行（Node.js 18+，无需 npm 安装）：

```bash
node --test tests/*.test.cjs
```

覆盖：

- **数值**：`tests/binomial-fixtures.json` 为 Python 任意精度**精确有理数**计算的 274 个 `P[Binomial(N,1/7)≥K]` 参照样本（N=1…1361，含 K=0/N、次正规数区、长尾求和区），页面实现须与之在相对误差 5e-13 内一致；另有固定核对点（58,13)/(58,14)、显著性阈值、边界与下溢显示、连续性修正 z。
- **算法**：原版引擎 1294 期逐期有序 7 码的 SHA-256 哈希回归 + 命中数 230/53/13；组合约束 1294 期哈希回归 + 217/47/10；组合约束逐期满足全部约束且恒为 7 个不同号码；合成号码池的最优解/扩池/同分排序/单数约束/和值约束用例；无未来信息（追加数据不改历史预测）；模型切换确定性；预热边界（60 期）。
- **前瞻与界面**：4 列明细表（不含单双/大小/波色回测列）；默认 2026-201 → 58 期 13 次命中、精确 p=0.0630 判"边缘/不显著"；起算期 2026-001/2023-061 的 258/53、1294/230；预热自动从 2023-061 起算；输入框与滑块双向同步；非法/超范围期号明确报错不静默回退。
- **缓存失效**：缓存键 = 数据版本 × 模型 × 起算期；重复运行命中缓存；区间、模型、数据任一变化即失效重算；模型切换同步清空缓存与旧随机对照。
- **蒙特卡洛**：Mulberry32 确定性；10,000 次对照可完成且经验 p 落在精确 p 的 5σ 模拟误差内；显示种子与 Wilson 区间；任务取消与旧结果清空。
- **页面卫生**：不出现模型版本号；组合约束开关默认关闭且默认规则名为"原评分＋原选码"。

`tests/helpers.cjs` 在 Node VM 中**直接执行 `index.html` 内的原始页面代码**，并提供最小 DOM/event-loop/localStorage 替身（含 `localStorage` 预置数据模拟"已同步"状态）——没有另写一份预测算法。固定核对数据（区间命中数与逐期预测哈希）保存在 `tests/expected.json`，对应数据固定到 2026-258（若仓库数据更多，核对也限定到该期号，不比较不同长度样本）。
