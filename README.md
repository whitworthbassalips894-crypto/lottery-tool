# 三中三 · 7码复式工具（含第 7 位特码记录）

蓝白配色的单页工具，卡片式布局、移动端优先。主推 7 码为**固定一组号码**（写在 `src/engine.js` 的 `FIXED_SEVEN`），每期都用同一组、不随开奖变化。开奖核对**只用每期前 6 个平码**；第 7 位特码单独记录、单独统计命中，不参与选号，因此加入特码不会改变任何一期的 7 码方案。

页面模块（顶栏锚点可直达）：

1. **最新开奖**：第 1~6 位平码 + 分隔符 + **第 7 位特码**（放大、蓝圈、标注「特码」），下方关键指标条给出有效期数、最新期、下期目标期、近 100 期三中三有奖率与 7 码中特率。
2. **下期 7 码复式推荐**：35 组三中三、一键复制、本档构成（波色／区间／单双／尾数），并给出这组号码的逐号波色/生肖。
3. **历史命中**：`特码命中` 与 `三中三命中` 两个视图分别展示，共用近 100 期／年份范围、期号搜索、仅看命中、分页加载与点击展开明细。
4. **特码开奖记录**：按期号由近到远展示每期第 7 位特码（波色球 + 日期 + 生肖），主推 7 码命中该特码的期次高亮，可每次多加载 30 期。
5. **开奖录入**：手动补录本期开奖（期号 + 6 位正码 + **第 7 位特码**），支持粘贴 7 个号码自动填入、日期按期号推算、撤销上条手动记录。
6. **数据同步**：「🔎 检查更新」只读上游文件开头约 1 KB，告诉你差几期、**不写入**；「🔄 一键同步」才下载完整数据并校验写入（期号连续性、重复、平码冲突、特码冲突）。卡片内常驻四格状态条：**本机最新期 / 内置快照 / 上游最新期 / 上次同步**，每种结果（新增 N 期、已是最新、本机超前、失败）都会写明原因与时间。

## 选号算法：固定 7 码

主推号码是**一组固定的 7 码**，写死在 `src/engine.js` 的 `FIXED_SEVEN`：

```js
const FIXED_SEVEN = Object.freeze([5, 8, 17, 21, 32, 38, 43]);
```

- 每期都用同一组，**不随开奖结果、期号或任何统计量变化**——刷新、换期号、同步新数据都不换号，方便长期跟号与对账。
- 这组号的来源：附件《7码版纯净版.html》v3.3 模型（饱和度 U 型曲线 + 频次 + 波色，只读第 7 位特码）在 2026-326 之前全部历史上的当期输出。移植版本与原版逐期比对 **1175 期，选号 100% 一致**。
- 需要换号时只改 `FIXED_SEVEN` 一处，回放、指标卡、一键复制文案会自动跟随。

### 这组号的实测成绩（不会比随机更好）

| 口径 | 固定 7 码实测（1786 期回放） | 随机 7 码 |
| --- | --- | --- |
| 三中三有奖率 | **2.69%**（48 期） | 3.10% |
| 平均每期命中平码 | **0.856 个** | 0.857 个 |
| 7 码中特码 | **14.05%**（251 期） | 14.29% |
| 返奖率（35 组 × 2 元） | **67.2%**（投入 125,020 元） | ≈76% |

号码固定也意味着**长期押同一注**：最长连续未中 **179 期**，当前连续未中 4 期。这与随机 7 码的长尾分布一致，不必因此判断「快出了」。

### 为什么不继续用统计模型

前几版内核在同一份数据上的表现，正好说明这些差异都是噪声：

| 内核 | 回放有奖率 | 平均命中 |
| --- | --- | --- |
| v3：连庄强热/回马旺尾/滞冷断档（20+ 个手调自由度） | 4.26% | 0.939 |
| v4：冷门反命中（近 36 期出现最少） | 2.69% | 0.814 |
| v5：每日随机（期号定种子） | 3.30% | 0.855 |
| **v6：固定 7 码（当前）** | **2.69%** | **0.856** |
| 随机理论值 | 3.095% | 0.857 |

- 号码频次前后半段 Spearman 仅 **-0.025**；近 40 期最热 7 码下期出现率 12.28%、最冷 7 码 11.95%、理论 12.24%——热/冷都不可外推。
- 全样本频次卡方 42.5（df=48，临界 65.2）、重现间隔均值 7.13 期（理论 7.17）、连续两期平码重叠 0.79 个（理论 0.735）：数据与独立随机开奖一致。

> ⚠️ 固定号码不改变中奖概率：7 码覆盖命中 ≥3 个平码 **3.10%/期**（平均 32.3 期一次、中位 22 期），每期 70 元投入的期望返奖约 **53.2 元（≈76%）**。

## 口径与规则

- **三中三**（不变）：7 码拆成 35 个三数组合，命中组数 = C(命中平码数, 3)，只核对前 6 个平码。回放按每组 2 元、中奖组总返奖 700 倍计算：35 组每期 70 元，每个中奖组合奖金 1,400 元（含本金），未计税费。
- **特码**（新增）：判定「当期主推 7 码是否包含开奖第 7 位特码」，统计命中期数、命中率、平均间隔、当前连错、最长连错与近 20 期命中，并对照随机基线 7/49 ≈ 14.3%。**特码只记录命中，不折算金额，也不并入三中三奖金。**
- **7码中特常驻**：`7码中特` 既是特码视图的核心列，也是三中三视图里固定的一列与一张指标卡，切换视图、年份范围、搜索或「仅看命中」都不会丢失特码命中记录；展开明细在两个视图下都同时给出特码与三中三信息。
- 开奖随机，模型不保证中奖；历史回放只使用每期之前的有效数据，属于事后模拟，并非实际历史投注。实际赔率、奖金及费用请以当地合法销售机构规定为准。

## 数据

- 内置 `data/draws.json` 是上游 `Number-selection-tool` 的快照：**1787 期（2022-001 ~ 2026-326，上游更新时间 2026-11-22 22:07 UTC）**，每期含前 6 位平码与第 7 位特码。与上一版快照共有的 1785 期逐期比对，平码、日期、特码 **0 处差异**，本次只新增 2026-325、2026-326 两期；更早的 1780 期平码与日期在改版时也已逐期校验一致。
- 数据源中 `2022-132` 的前 6 码含重复号码，按原口径整期排除；固定 7 码不依赖历史条数，任何一期都能给出完整 7 码，回放仍保留「不足 7 码则跳过」的兜底。期号按年内序号规则推算，购买前请核对官方期号。
- 数据源为 `https://whitworthbassalips894-crypto.github.io/Number-selection-tool/data/draws.json`（上游一般**每天开奖后新增一期**），依赖该网站继续更新、跨域可用及网络畅通；仅追加连续有效的期号，冲突或缺口不写入。本机旧数据缺少特码时会自动回填（不改动既有平码）。
- 「检查更新」用 `Range: bytes=0-1023` 只取文件开头，正则读出 `latestId` / `updatedAt` 后按期内序号推算差几期；若上游忽略分段请求、直接返回完整文件，则顺手完成一次正式同步（不浪费已下载的流量）。是否支持分段请求会记在本机，支持时**下次打开页面自动检查**并提示，但不会自动写入。
- 打开页面时本机备份与内置快照**双向合并**（`mergeLocal`）：站点更新内置快照后本机备份会变旧、本机同步过更新的数据时内置快照会变旧，两种情况都能正常合上；同一期两边都有时以官方（内置快照）为准，只补缺的特码，手动记录与官方号码不一致时会明确列出「已按官方数据计」而不是静默覆盖。
- 同步结果、上次同步时间（含失败）与手动补录记录都只保存在当前浏览器（存储键 `three_in_three_sync_v1`，schema 2；附加 `lastSync`、`rangeOk` 两个元信息键，旧版本数据读取时会忽略）。
- `sw.js` 的离线缓存对上游数据路径 `/Number-selection-tool/` **始终直连**（同域也不吃缓存），避免“上游已更新却读到旧缓存”；缓存名随数据与代码一起提升（当前 `three-in-three-v8`）。
- 手动补录要求期号紧接当前最新一期、7 个号码互不重复且在 1~49；手动记录被上游数据收录（号码一致）后不再算手动记录，撤销只在它仍是最新一期时可用，避免造成期号缺口。
- 按用户要求，页面初始化时删除当前浏览器本工具的快乐8手动记录及玩法设置；其他设备与其他站点数据不受影响。

## 点了同步却没变化？

同步状态一定会写明原因，常见四种：

| 提示 | 含义 | 该怎么做 |
| --- | --- | --- |
| `✅ 同步完成：新增 N 期（…）` | 已写入并刷新全部模块 | 无需操作 |
| `✅ 已是最新，没有新期次可加` | 本机与上游同期，上游当天还没发布新期次 | 等发布后再点；**这不是失败**。上游近期多在 UTC 22:00 前后（新加坡时间次日 06:00 前后）发布当天开奖 |
| `ℹ️ 无需同步：本机最新期已超前上游` | 你手动补录的期次比上游还新 | 等上游发布同一期后会自动核对，号码不一致会提示冲突 |
| `❌ 同步失败，未更改现有数据` | 网络、跨域或数据校验（平码／特码冲突、期号缺口）问题 | 按提示检查网络后重试；与手动补录冲突时可先「撤销上条手动」 |

另外：状态条里的「内置快照」是打包进页面的那一期，「本机最新期」才是你当前用的数据；两者不同时说明本机已同步或已手动补录。若页面本身像是旧版本，请强制刷新（Service Worker 缓存名已随本次数据提升）。

## 视觉与移动端

- 蓝白配色：浅蓝白底 `#eef3fb`、白卡片、深蓝灰文字 `#152438`、主蓝 `#1d4ed8`；红／蓝／绿只用于号码波色（数据色），琥珀色只用于「命中」高亮。
- 移动端：吸顶导航可横向滑动、按钮通栏、指标卡与特码记录改单列／双列、号码球与表格缩小，宽表可横向滑动且**期号列吸附在左侧**，并给出滑动提示。
- 全局 `[hidden]{display:none !important}`：作者样式里的 `display:inline-flex` 等会覆盖浏览器默认的 `[hidden]`，曾导致「加载更多」加载到底后按钮仍可见、再点没反应；现在加载到底会隐藏按钮并提示「已显示全部 N 期」。

## 开发与自检

```sh
npm install          # 只有端到端 DOM 测试需要 jsdom（可选）
npm test             # 等价于 node --test tests/*.test.cjs
npm start            # 本地静态服务，访问 http://localhost:8000
```

- `tests/core.test.cjs`：快照完整性、固定 7 码内核（与历史/期号无关、`fixedSeven()` 返回副本、换号只改一处）、特码不影响选号、回放与随机基线同一水平、金额口径、特码命中统计、同步冲突／缺口／回填、手动补录校验与撤销。
- `tests/ui.test.cjs`：轻量假 DOM 下的初始化、渲染、复制、同步与录入流程，以及同步辅助（期数差、时间格式、状态条四格与提示 pill）。
- `tests/dom.test.cjs`：jsdom 端到端（真实解析 `index.html` 并模拟点击、输入、勾选与同步），并覆盖检查更新（上游多期／同期／忽略 Range）、一键同步、本机超前上游、网络失败、刷新后恢复与自动检查、`sw.js` 缓存策略；未安装 jsdom 时自动跳过。
- 改动前端文件时请同步提升 `src/app.js` 的 `APP_BUILD` 与 `sw.js` 的 `CACHE_NAME`，否则旧缓存会与新代码混用。

如用 GitHub Pages 部署，请使用静态网站方式访问；一键同步需联网。
